# v0.3.1 Release Hardening Plan

Status: local verification complete; awaiting remote evidence and publication

## Objective

Close the release gap left by the facade-removal tag without weakening the parity, coverage,
runtime, or supply-chain gates. Publish the corrected source and six-platform runtime bundle from
an exact commit on `main`.

## Cleanup Sequence

1. Lock modern Client/Thread behavior with regression tests.
2. Remove unreachable lazy-thread state left behind by the v0.1 facade.
3. Restore root-package coverage to at least 85% with observable modern API tests and config edge
   cases; do not lower thresholds.
4. Replace stale compatibility evidence names and avoid duplicate CI/runtime runs for feature
   branch pushes and tag pushes.
5. Add package documentation, executable examples, vulnerability scanning, and deterministic
   timing tests where practical without adding runtime dependencies.
6. Update release instructions so tags are created only by the evidence-gated release workflow.
7. Run formatting, unit, integration, race, static analysis, vulnerability, generator, coverage,
   example, and six-target cross-build verification.
8. Merge through a reviewed PR, protect `main`, run stress/runtime evidence on the exact merge
   commit, and publish `v0.3.1` without moving the existing public `v0.3.0` tag.

## Acceptance Criteria

- `Thread` contains only state required by the materialized app-server thread contract.
- Modern thread/turn/login/goal behavior remains source-compatible with v0.3.0.
- Root statement coverage is at least 85%; appserver/router/runtimebin remain at least 90%.
- CI evidence names existing tests and all CI jobs pass on the release commit.
- CI and runtime workflows validate feature branches through PRs, rerun on the merged main commit,
  and do not duplicate work for feature-branch or tag pushes.
- `govulncheck` and existing static/race/fuzz gates pass.
- CodeQL `security-extended` analysis passes, and workflow actions use maintained Node 24 majors.
- Package documentation renders a useful overview and executable examples pass.
- `main`, the release tag, release evidence, and GitHub Release target the same commit.
- The release contains six runtime archives, signed manifest, and release bundle.

## Non-Goals

- Do not move or rewrite the already-public `v0.3.0` tag.
- Do not remove shared v0.3 option types or no-context convenience methods in this patch release.
- Do not lower coverage, stress, signature, provenance, or platform requirements.

## Verification Record

The release candidate must retain the following local evidence before it is merged:

- `go test ./...`, `go test -tags=integration ./...`, and `go test -race ./...` pass with Go
  1.25.12.
- `go vet ./...`, `staticcheck@2025.1.1`, `govulncheck@v1.6.0`, and CodeQL pass.
- The generator drift check and all example builds pass.
- Coverage is at least 85% for the root package and 90% for appserver, router, and runtimebin.
- `go build ./...` passes with CGO disabled for Darwin, Linux, and Windows on amd64 and arm64.
- An independent code review reports no correctness, concurrency, CI schema, or cross-platform
  blockers.

Remote evidence remains mandatory on the exact merge commit. Record the successful workflow run
IDs in the release bundle, then confirm `main`, `v0.3.1`, and the GitHub Release resolve to that
same commit. The plan is complete only after those checks and all nine release assets are present.
